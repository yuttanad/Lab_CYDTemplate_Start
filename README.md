# Level 2 / Lab_Template_Start — เตรียมบอร์ด CYD ให้พร้อมใช้ LVGL

โปรเจกต์ตั้งต้นของ **ESP32 CYD Dev Level 2** สำหรับบอร์ด **ESP32-2432S028 (CYD)** จอ 2.8" 320×240 + จอสัมผัส XPT2046
ใช้ **VS Code + PlatformIO**, **LVGL 8.3** และ **TFT_eSPI** หน้าจอเป็น**ภาษาไทย** (ฟอนต์ Chakra Petch)

ก่อนเริ่ม Lab อื่นของ Level 2 ทุกคนต้องผ่าน Lab นี้ก่อน เพื่อให้แน่ใจว่าบอร์ดของตัวเอง:

1. **จอแสดงสี ทิศ และข้อความถูกต้อง** แก้อาการสีกลับ แดงสลับน้ำเงิน หรือภาพกลับด้านได้**บนจอ** ไม่ต้องแก้โค้ด และจำค่าไว้ถาวร
2. **จอสัมผัสแตะตรงจุดอย่างแม่นยำ** โดย calibrate 5 จุด + จุดตรวจสอบ แล้ววัดผลด้วยการทดสอบ 9 จุด
3. **ไฟ RGB LED** และ**ลำโพง**ทำงาน

> **สถานะการตรวจสอบ (อ่านก่อน):** โปรแกรม **build ผ่านทั้ง 2 env** (`cyd`, `cyd_st7789`) ไม่มี warning จากโค้ดของ Lab นี้
> ใช้ RAM 23.2% (76 KB) และ Flash 18.7% (≈ 575 KB จาก 3 MB)
> **ทดสอบบนบอร์ดจริง (ILI9341, env `cyd`) บางส่วนแล้ว 2026-10-16:** บูตได้ calibrate ผ่าน (fit เฉลี่ย 1.35 px, มากสุด 1.78 px, จุดตรวจสอบ 4.05 px)
> **ทดสอบบอร์ดจอ ST7789 (env `cyd_st7789`) แล้ว 2026-10-27:** บูตได้ ค่าจอเริ่มต้นถูก (สีตรง ภาพไม่กลับ) calibrate ผ่าน (เฉลี่ย 3.06 px, มากสุด 3.72 px, จุดตรวจสอบ 1.92 px) แตะตรงจุด
> ส่วนที่เหลือดูตาราง "สิ่งที่ยังไม่ได้ยืนยัน" ท้ายไฟล์

## 2. เริ่มใช้งาน

1. เปิดโฟลเดอร์ `Lab_Template_Start` ใน VS Code (ต้องเปิดโฟลเดอร์ที่มี `platformio.ini` โดยตรง)

4. **บูตครั้งแรก** จะเห็น splash แล้วเข้าหน้า **Calibrate จอสัมผัส** เอง (หัวข้อ 5)

## 4. แท็บ "จอภาพ": ตรวจและแก้จอ

```
┌──────────────────────────────────────┐
│ จอภาพ │ สัมผัส │ ไฟRGB │ เสียง │ ระบบ │  ← แตะชื่อแท็บเพื่อเปลี่ยน (ปิดการปัดไว้)
├──────────────────────────────────────┤
│ 1) สีพื้นฐาน: ช่องสีต้องตรงกับชื่อ        │
│ [R][G][B][Y][C][M][W][K]             │
│ ▁▂▃▄▅▆▇█ แดง / เขียว / น้ำเงิน / เทา      │
│ 2) แก้ปัญหาจอ (จำค่าอัตโนมัติ)            │
│ กลับสี (ขาว<->ดำ)               [  o] │
│ สลับ แดง<->น้ำเงิน (BGR)          [  o] │
│ กลับซ้าย-ขวา                    [  o] │
│ กลับบน-ล่าง                     [  o] │
│ ชิป ILI9341   MADCTL = 0x28          │
│ [ทดสอบเต็มจอ] [ค่าเริ่มต้น]              │
│ ความสว่างจอ 80%  ━━━━━━━━━○──        │
│ 3) ข้อความและฟอนต์ ...                 │  ← เลื่อนลงดูต่อ
└──────────────────────────────────────┘
```
(ภาพ ASCII วาดประกอบ ไม่ใช่ภาพจริง)

### อาการและวิธีแก้

| อาการที่เห็น | เปิด/ปิดสวิตช์ |
|---|---|
| ช่อง W เป็นดำ, K เป็นขาว, สีเหมือนฟิล์มเนกาทีฟ | **กลับสี** |
| ช่อง R เป็นน้ำเงิน และ B เป็นแดง (G ถูก) | **สลับ แดง<->น้ำเงิน** |
| ตัวหนังสือกลับด้านเหมือนส่องกระจก | **กลับซ้าย-ขวา** |
| ภาพกลับหัว (แท็บอยู่ล่าง ตัวหนังสือคว่ำ) | **กลับบน-ล่าง** |
| ภาพหมุน 180 องศา (ตัวหนังสืออ่านได้ แต่กลับหัว) | เปิด**ทั้งกลับซ้าย-ขวาและกลับบน-ล่าง** |

- ค่าจะ**บันทึกทันที**ที่สลับสวิตช์ ปิดเครื่องแล้วเปิดใหม่ก็ยังอยู่
- กลับซ้าย-ขวา หรือกลับบน-ล่าง แล้ว**ไม่ต้อง calibrate ใหม่** เพราะโปรแกรมกลับสมการจอสัมผัสตามให้เอง
- **ทดสอบเต็มจอ:** แตะไปทีละหน้า 7 หน้า ได้แก่ แดง, เขียว, น้ำเงิน, ขาว, ดำ, ไล่ระดับสี และตาราง (มีป้ายสี่มุม + ขอบแดง 1 px ซึ่งต้องเห็นครบทั้ง 4 ด้าน ถ้าขาดด้านใดแปลว่าภาพถูกตัด)
- **ตั้งค่าผิดจนมองไม่เห็นอะไร:** กดปุ่ม **BOOT ค้าง 1 วินาที** (หรือพิมพ์ `r` ใน Serial) จะกลับเป็นค่าเริ่มต้น

### ความรู้: จอรู้ได้อย่างไรว่าจะวาดทิศไหน สีไหน

ชิปจอ ILI9341 / ST7789 มีคำสั่ง 2 กลุ่มที่โปรแกรมนี้ใช้ (`src/hal_display.cpp`)

| คำสั่ง | ความหมาย |
|---|---|
| `INVON` (0x21) / `INVOFF` (0x20) | กลับสีทุกพิกเซล |
| `MADCTL` (0x36) 1 ไบต์ | บิต 7 **MY** กลับลำดับแถว · บิต 6 **MX** กลับลำดับคอลัมน์ · บิต 5 **MV** สลับแถว/คอลัมน์ (หมุน 90° เป็นแนวนอน) · บิต 3 **BGR** ลำดับสีของแผง |

เมื่อเป็นแนวนอน (MV = 1) **MY = กลับซ้าย-ขวา** และ **MX = กลับบน-ล่าง**
ตัวอย่าง ILI9341 ค่าตั้งต้นแนวนอนคือ `MV | BGR = 0x20 | 0x08 = 0x28` ถ้าเปิด "กลับซ้าย-ขวา" จะเป็น `0x28 ^ 0x80 = 0xA8`
ค่า MADCTL ปัจจุบันแสดงอยู่ใต้สวิตช์ ดูได้ว่าเปิดสวิตช์ไหนแล้วบิตไหนเปลี่ยน

### ข้อความภาษาไทย

LVGL ไม่มีฟอนต์ไทยในตัว Lab นี้จึงสร้างฟอนต์ `font_th_16` (ตัวปกติ) และ `font_th_24` (ตัวหนา) จาก **Chakra Petch** ด้วย `lv_font_conv`
ในฟอนต์มี ASCII, อักษรไทยทั้งหมด (U+0E01–0E5B), เครื่องหมาย `°` และสัญลักษณ์ `LV_SYMBOL_*` ของ LVGL

- ในโค้ดพิมพ์ภาษาไทยตรงๆ ได้เลย เช่น `lv_label_set_text(l, "อุณหภูมิ 25.5°C");` (ไฟล์ต้องบันทึกเป็น UTF-8)
- **ข้อจำกัด 1:** LVGL 8 จัดตำแหน่งวรรณยุกต์ซ้อนสระบนไม่ได้ (เช่น "ที่", "นี้") วรรณยุกต์จึงอาจทับสระบนเล็กน้อย ให้ตรวจในหน้า "ข้อความและฟอนต์"
- **ข้อจำกัด 2:** ภาษาไทยไม่เว้นวรรคระหว่างคำ LVGL จึงตัดบรรทัดกลางคำ ถ้าข้อความยาว ให้**เว้นวรรคเอง**ตรงที่ตัดบรรทัดได้
- ตัวอักษรที่ไม่อยู่ในฟอนต์ (เช่น `·` `→` emoji) จะไม่แสดง ถ้าต้องการเพิ่ม ให้แก้ช่วงตัวอักษรใน `tools/gen_lvgl_fonts.ps1` แล้วสร้างใหม่

```powershell
powershell -ExecutionPolicy Bypass -File tools\gen_lvgl_fonts.ps1
```

(ต้องมี Node.js สคริปต์จะเรียก `npx lv_font_conv@1.5.2` ให้เอง)

## 5. Calibrate จอสัมผัสแบบแม่นยำ

### ขั้นตอนบนจอ

1. ขึ้นเป้ากากบาทสีเขียวทีละจุด: **บนซ้าย → บนขวา → ล่างขวา → ล่างซ้าย → กลางจอ**
2. แตะ**กลางเป้า**แล้ว**กดค้าง**จนแถบด้านล่างเต็ม (ประมาณ 0.2 วินาที) จะมีเสียงปี๊บและข้อความ "ดีมาก ยกนิ้วขึ้นได้" แล้วจึงยกนิ้ว
3. ครบ 5 จุดแล้วจะขึ้น **จุดตรวจสอบ** อีก 1 จุด แตะเหมือนเดิม
4. ผ่านทุกขั้นจะขึ้น `Calibrate สำเร็จ` พร้อมตัวเลขความแม่นยำ แล้วกลับหน้าหลักเอง

calibrate ใหม่ได้ที่แท็บ **สัมผัส → Calibrate (กดค้าง)** หรือพิมพ์ `c` ใน Serial
ถ้าเข้ามาแล้วไม่แตะเลย 20 วินาที จะยกเลิกและใช้ค่าเดิม

| ข้อความที่ขึ้น | ความหมาย / วิธีแก้ |
|---|---|
| `ยกนิ้วเร็วไป กดค้างจนแถบเต็ม` | ยกนิ้วก่อนเก็บค่าครบ ให้แตะใหม่ที่เป้าเดิม |
| `นิ้วยังไม่นิ่ง กดค้างไว้นิ่งๆ` | ค่าดิบแกว่งเกิน `CAL_MAX_SPREAD_RAW` ให้กดแรงสม่ำเสมอ หรือใช้ปากกา |
| `แตะผิดจุด ...` / `คลาดเคลื่อน ... px` | ค่าที่ได้ไม่เข้ากับรูปสี่เหลี่ยม เริ่มใหม่จากจุดที่ 1 |
| `จุดตรวจสอบคลาดเคลื่อน ... px` | สมการใช้กับจุดที่ไม่ได้ใช้คำนวณได้ไม่ดี เริ่มใหม่ |

### ความรู้: ทำไมแบบนี้จึงแม่นกว่า Lab 9 (Level 1)

| | Lab 9 (Level 1) | Lab นี้ |
|---|---|---|
| สมการ | `x = a + b·u`, `y = c + d·v` แยกแกน | **affine** `x = a·u + b·v + c`, `y = d·u + e·v + f` |
| แกนสลับ / กลับด้าน | ต้องตรวจเองแล้วตั้ง `swapXY` | ได้จากสมการเอง (เมื่อแกนสลับ `b`, `d` จะใหญ่ ส่วน `a`, `e` ใกล้ 0) |
| แผ่นสัมผัสติดเอียงเล็กน้อย | แก้ไม่ได้ | แก้ได้ (ค่า `b`, `d` เล็กๆ ชดเชยความเอียง) |
| ค่าต่อเป้า | ค่าเฉลี่ย 10 ค่า | ทิ้ง 4 ค่าแรก แล้วใช้ **มัธยฐาน** ของ 16 ค่า + ตรวจว่านิ้วนิ่ง (IQR) |
| จำนวนจุด | 4 (พอดีกับจำนวนตัวแปร) | 5 จุด ใช้ **least squares** เฉลี่ยความผิดพลาดของแต่ละจุด |
| ตรวจผล | ย้อนกลับ 4 จุดเดิม | ตรวจทั้ง 5 จุด **และจุดตรวจสอบที่ไม่ได้ใช้คำนวณ** |

- **ทำไมทิ้งค่าแรก:** ตอนนิ้วเพิ่งแตะ แรงกดยังเพิ่มขึ้นเรื่อยๆ พิกัดที่อ่านได้จึงยังเลื่อนอยู่
- **ทำไมใช้มัธยฐาน:** ถ้ามีค่าเพี้ยน 1 ค่า (เช่น 900 ในกลุ่มที่เหลือราว 2,000) ค่าเฉลี่ยจะเพี้ยนตาม แต่มัธยฐานไม่เปลี่ยน
- **least squares:** หา `a…f` ที่ทำให้ "ผลรวมของระยะผิดพลาดยกกำลังสอง" ของทั้ง 5 จุดน้อยที่สุด (`touchCalFit()` ใน `src/hal_touch.cpp`)
- **จุดตรวจสอบ:** เป็นแบบเดียวกับข้อสอบที่ไม่ได้ให้ดูก่อน ถ้าสมการดีจริง จุดที่ไม่ได้ใช้คำนวณต้องตรงด้วย

### ทดสอบความแม่นยำ 9 จุด

แท็บ **สัมผัส → ทดสอบ 9 จุด**: แตะกลางเป้าทีละจุด แต่ละครั้งจะมีจุดสีขึ้นตรงตำแหน่งที่โปรแกรมอ่านได้

| สีจุด | ระยะห่างจากเป้า |
|---|---|
| เขียว | ≤ 4 px (ดีมาก) |
| เหลือง | ≤ 8 px (ใช้งานได้) |
| แดง | > 8 px (ควร calibrate ใหม่) |

จบ 9 จุดจะสรุป **ค่าเฉลี่ย** และ **ค่ามากสุด** (Serial พิมพ์ `[ACC] ...` ทุกจุด)
ปุ่ม LVGL ที่เล็กที่สุดใน Lab ต่อๆ ไปควรกว้างไม่น้อยกว่า **2 เท่าของค่ามากสุด** ที่วัดได้

## 6. แท็บ "ไฟ RGB" และ "เสียง"

**ไฟ RGB** (LED ด้านหลังบอร์ด)
- แถบเลื่อน แดง / เขียว / น้ำเงิน ค่า 0–255 และแถบสีบนจอแสดงสีที่ผสมได้
- ปุ่มสีสำเร็จรูป 8 สี
- **ทดสอบอัตโนมัติ:** ไล่ทีละสีทุก 0.7 วินาที และบอกว่า "LED ต้องเป็นสีอะไร" ถ้าสีไม่ตรงคำบอก แปลว่าขาใน `board_config.h` ไม่ตรงกับบอร์ด หรือต้องแก้ค่า `LED_ACTIVE_LOW`
- **สายรุ้ง:** ไล่สีต่อเนื่องรอบวงล้อสี

**เสียง** (ลำโพงที่ขั้ว SPEAK, GPIO26)
- ความดัง ปิด / เบา / กลาง / ดัง (คือ duty ของ PWM 0 / 24 / 96 / 512 จาก 1023) จำค่าไว้
- เสียงทดสอบ: บี๊ป 1 kHz, ไล่โน้ต C5–C6, เพลงสั้น, กวาดความถี่ 200→4000 Hz, หยุด
- เปียโน 8 คีย์ และแถบเลือกความถี่ 100–5000 Hz (ระหว่างลากจะได้ยินเสียงตาม)
- แตะจอทุกครั้งมีเสียงติ๊กสั้นๆ (ปิดได้ที่ `CLICK_SOUND` ใน `app_config.h`)

ถ้าไม่มีเสียงเลย ให้ตรวจว่าเสียบลำโพงที่ขั้ว **SPEAK** และความดังไม่ใช่ "ปิด"

## 7. แท็บ "ระบบ" และคำสั่ง Serial

แท็บระบบแสดงรุ่นชิป, ความเร็ว CPU, flash, ขนาดโปรแกรม, ชิปจอ, เวอร์ชัน LVGL, สาเหตุที่บอร์ดเริ่มทำงาน, heap ว่าง และค่าดิบของ LDR

| คำสั่ง | ทำอะไร |
|---|---|
| `h` | แสดงรายการคำสั่ง |
| `i` | สถานะ (เหมือนบรรทัด `[STATUS]` ที่พิมพ์ทุก 5 วินาที) |
| `c` / `k` | เริ่ม calibrate / แสดงสมการ calibrate และค่าดิบล่าสุด |
| `d` / `r` | แสดงค่าจอ (รวม MADCTL) / รีเซ็ตค่าจอเป็นค่าเริ่มต้น |
| `t` | เปิด/ปิดการพิมพ์ `[TOUCH] down/up ...` ทุกครั้งที่แตะ |
| `l` / `s` | ทดสอบ LED แดง→เขียว→น้ำเงิน→ขาว→ดับ / เล่นไล่โน้ต |

ตัวอย่างบรรทัดใน Serial (รูปแบบตามโค้ด ตัวเลขเป็นตัวอย่างสมมุติ ไม่ใช่ผลจริง):

```
[DISP] driver=ILI9341 saved invert=0 bgr=1 flipH=0 flipV=0 MADCTL=0x28
[CAL] point 1 raw = (452, 610)
[CAL] fit  x = 0.08912*u -0.00041*v -12.3   y = 0.00052*u +0.06810*v -13.9   rms 1.21 px  max 1.87 px
[CAL] verify target (250,165) -> (251.4,163.9) error 1.78 px
[ACC] average 2.3 px  worst 4.1 px  -> ok
```

## 8. ลำดับการตรวจบอร์ด (เช็คลิสต์ผ่าน Lab)

- [ ] upload ได้ และเห็น splash `ESP32 CYD Dev Level 2` ภาษาไทยอ่านได้
- [ ] calibrate 5 จุด + จุดตรวจสอบสำเร็จ (จดค่า "เฉลี่ย / มากสุด / จุดตรวจสอบ" ไว้)
- [ ] แท็บจอภาพ: ช่องสี R G B W K ตรงชื่อ (แก้ด้วยสวิตช์ถ้าไม่ตรง) และ**ทดสอบเต็มจอ**ครบ 7 หน้า ขอบแดงครบ 4 ด้าน ป้ายมุมตรงตำแหน่ง
- [ ] รีเซ็ตบอร์ด (ปุ่ม EN) แล้วค่าจอ ความสว่าง และ calibrate ยังอยู่
- [ ] ทดสอบ 9 จุด ได้ค่ามากสุด ≤ 8 px (จดผลไว้)
- [ ] ไฟ RGB: ทดสอบอัตโนมัติ สี LED ตรงกับคำบอกทุกสี
- [ ] เสียง: ได้ยินทุกระดับความดัง เปียโนครบ 8 คีย์
- [ ] อธิบายได้ว่า MADCTL บิต MX / MY / MV / BGR ทำอะไร
- [ ] อธิบายได้ว่าทำไม calibrate แบบ affine + least squares + จุดตรวจสอบ จึงแม่นและเชื่อถือได้กว่าแบบ 4 จุดแยกแกน

## 11. นำไปต่อยอดใน Lab ถัดไป

1. **เพิ่มแท็บ:** เขียน `ui_xxx_tab(lv_obj_t *tab)` แบบเดียวกับ `ui_led_tab` แล้วเพิ่มในตาราง `tabs[]` ใน `ui_main.cpp`
2. **ใช้ฟังก์ชันช่วย:** `ui_card()` (การ์ดเรียงแนวตั้ง), `ui_row()` (แถวปุ่ม), `ui_btn()`, `ui_switch_row()`, `ui_label()`
3. **ลากในแท็บ:** widget ที่ลาก (แถบเลื่อน, พื้นที่วาด) ให้เรียก `ui_no_scroll(widget)` หน้าจะได้ไม่เลื่อนตามนิ้ว
4. **เสียง:** `hal::soundTone(hz, ms)`, `hal::soundPlay(hal::Melody::Success)` ทำงานใน task แยก ไม่ทำให้ UI หน่วง
5. **ต่อเซนเซอร์:** ใช้ I2C ที่ GPIO27 (SDA) / GPIO22 (SCL) **ห้ามใช้ GPIO21** (ขาไฟหลังจอ จอจะกะพริบ)
6. **ห้ามใช้ `delay()` ยาวๆ** ใน callback ของ LVGL ให้ใช้ `lv_timer_create()` แทน (ดูตัวอย่าง `tick()` ใน `ui_led.cpp`)

## 12. ปัญหาที่พบบ่อย

| อาการ | สาเหตุ / วิธีแก้ |
|---|---|
| ภาพถูกตัด / เลื่อนครึ่งจอ / มีขยะขอบจอ | เลือก env ผิดชิป (หัวข้อ 3) |
| สีผิด / กลับด้าน | แท็บจอภาพ (หัวข้อ 4) |
| ตั้งค่าจอผิดจนมองไม่เห็น | กด BOOT ค้าง 1 วินาที หรือ Serial `r` |
| มีจุดสุ่ม / เส้นขยะบนภาพ | ลด `SPI_FREQUENCY` ใน `platformio.ini` เป็น `40000000` |
| แตะแล้วไม่ตรง | calibrate ใหม่ ใช้ปากกาปลายมน แล้วทดสอบ 9 จุด |
| แตะไม่ติด / ต้องกดแรงมาก | ลด `TOUCH_Z_MIN` (ดูค่า `z` สดในแท็บสัมผัส) |
| calibrate ขึ้น "นิ้วยังไม่นิ่ง" บ่อย | กดแรงสม่ำเสมอ ใช้ปากกา หรือเพิ่ม `CAL_MAX_SPREAD_RAW` |
| LED สีไม่ตรง / ตั้ง 255 แล้วดับ | ตรวจ `LED_PIN_*` และ `LED_ACTIVE_LOW` ใน `board_config.h` |
| ไม่มีเสียง | เสียบลำโพงที่ขั้ว SPEAK, ความดังไม่ใช่ "ปิด" |
| ภาษาไทยบางตัวไม่แสดง | ตัวอักษรนั้นไม่อยู่ในฟอนต์ ดูหัวข้อ 4 "ข้อความภาษาไทย" |
| upload ไม่ผ่าน | ปิด Serial Monitor / กด BOOT ค้างตอน `Connecting...` / ถอดสาย USB แล้วเสียบใหม่ |

## 13. สิ่งที่ยังไม่ได้ยืนยัน (ผู้ทดสอบ/ผู้สอนควรตรวจและบันทึก)

| ข้อ | สถานะ |
|---|---|
| build ผ่านทั้ง `cyd` และ `cyd_st7789` | **ยืนยันแล้ว** (ไม่มี warning จากโค้ดของ Lab นี้) |
| บูตบนบอร์ดจริง (ILI9341) | **ยืนยันแล้ว** จาก Serial: `driver=ILI9341 defaults ... MADCTL=0x28`, heap ว่าง ≈ 208 KB, stack ของ loop เหลือ ≈ 12.5 KB |
| อ่าน XPT2046 + calibrate 5 จุด + จุดตรวจสอบ | **ยืนยันแล้ว** จาก Serial: `x = 0.08953*u +0.00038*v -20.8  y = 0.00055*u +0.06784*v -21.1  fit rms 1.35 max 1.78 verify 4.05 px` (ค่า `b`, `d` ใกล้ 0 = แกนไม่สลับ ไม่เอียง) ค่าดิบของมุมบนขวาสองรอบต่างกันเพียง 3–6 หน่วย (≈ 0.5 px) ตัวเลขชุดนี้เป็นของบอร์ดต้นแบบตัวเดียว |
| calibrate ที่ล้ม จะถูกปฏิเสธและเริ่มใหม่ | **ยืนยันแล้ว** รอบที่จุดที่ 1 ถูกนับผิดตำแหน่ง ได้ `max 104.69 px` แล้วโปรแกรมเริ่มใหม่เองตามที่ออกแบบ (สาเหตุคือบั๊กนิ้วค้างจากปุ่ม ดูแถวถัดไป) |
| เริ่ม calibrate จากปุ่มกดค้าง แล้วนิ้วยังอยู่บนจอ | **พบบั๊กและแก้แล้ว** (เพิ่มสถานะ `WaitLift` รอยกนิ้วก่อนรับแต่ละเป้า) upload แล้ว **ยังไม่ได้ทดสอบ** ด้วยการกดปุ่ม Calibrate ค้าง |
| ค่าที่จำถาวรโหลดกลับหลัง upload ใหม่ + รีเซ็ต | **ยืนยันแล้ว** จาก Serial: `[CAL] loaded ...` สมการเดิม และ `vol=LOW` ตามที่ตั้งไว้ก่อน upload ตัวแก้ ไม่มี error ของ NVS และไม่มีคำเตือนเรื่องตัวอักษรที่ฟอนต์ไม่มีแล้ว |
| ความดังเปลี่ยนจากจอได้ | **เห็นใน Serial** (`vol=MID → OFF → LOW → HIGH`) ยังไม่ได้ยืนยันว่าได้ยินเสียงจริงทุกระดับ |
| PWM ของ LED / ไฟหลังจอ | นำมาจาก Template ที่ทดสอบบนบอร์ดจริงแล้ว ยังไม่ได้ยืนยันในโปรเจกต์นี้ |
| ภาษาไทยแสดงถูก อ่านได้ ไม่ล้นแท็บ/ปุ่ม | **ยังไม่ได้ดูจอจริง** (Serial เตือนว่าไม่มีตัว `·` U+00B7 ในหน้า splash แก้แล้วเป็นเครื่องหมายขีดตั้ง) |
| สวิตช์ "กลับซ้าย-ขวา" ใช้บิต MY และ "กลับบน-ล่าง" ใช้บิต MX | **อนุมานจากโค้ด TFT_eSPI** (rotation 1 = `MV`, rotation 5 = `MV|MX` ที่ไลบรารีใช้วาด BMP กลับบน-ล่าง) ยังไม่ได้ทดสอบบนจอจริง ถ้าสลับกัน ให้สลับ `TFT_MAD_MY` / `TFT_MAD_MX` ใน `writeToPanel()` |
| ค่าเริ่มต้นของ ST7789 (BGR / invert) ตรงกับบอร์ด USB-C | **ยืนยันแล้ว 2026-10-27** บนบอร์ดจอ ST7789 จริง (env `cyd_st7789`): Serial `driver=ST7789 defaults invert=0 bgr=1 flipH=0 flipV=0 MADCTL=0x68`, heap ว่าง ≈ 208 KB ผู้ทดสอบดูจอจริง: **สีแดง/เขียว/น้ำเงินตรง ภาพไม่กลับด้าน** ไม่ต้องปรับค่าจอ |
| calibrate บนบอร์ด ST7789 | **ยืนยันแล้ว 2026-10-27** `x = 0.08545*u -0.00138*v -7.5  y = -0.00017*u +0.06810*v -20.1  fit rms 3.06 max 3.72 verify 1.92 px` ผ่านเกณฑ์ 6 / 7 px และผู้ทดสอบยืนยันว่าแตะตรงจุด (ค่าดิบมุมจอ ≈ 480–3450 ใกล้บอร์ด ILI9341) |
| กลับด้านจอแล้วจอสัมผัสยังตรง (กลับสมการตาม) | **ยังไม่ได้ทดสอบ** |
| เกณฑ์ 6 / 7 px เหมาะกับบอร์ดทั้งห้อง | ผ่านบนบอร์ดต้นแบบ 1 ตัว ควรเก็บผลจากบอร์ดหลายตัวก่อนสรุป |
| ทดสอบ 9 จุด, ไฟ RGB, เสียง, ปุ่ม BOOT รีเซ็ตค่าจอ | **ยังไม่ได้ทดสอบ** |
| ตัวเลขใน Serial และภาพ ASCII ในไฟล์นี้ | วาดประกอบ / ตามรูปแบบในโค้ด ไม่ใช่ผลจริง |
